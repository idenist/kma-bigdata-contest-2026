# 0623 작업기획서

## 0. 문서 목적

본 문서는 `0623_모델실패원인분석_및_방향수정계획.md`의 결론에 따라, 남은 기간 동안 수행할 실제 작업 순서와 산출물을 구체화하기 위한 실행 계획서이다.

현재 전처리 파이프라인은 README 기준으로 이미 실행 완료된 상태이며, 시간이 부족한 상황에서 기상·산림·지형·전력설비 피처를 다시 생성하는 것은 리스크가 크다. 따라서 본 작업계획은 기존 전처리 산출물을 최대한 고정하고, 지도학습 모델링 대신 **전력설비 주변 산불 위험도 우선순위 산정 모델**을 완성하는 데 초점을 둔다.

---

## 1. 최종 방향 요약

### 1.1 중단 또는 보류할 작업

다음 작업은 더 이상 메인 작업으로 진행하지 않는다.

```text
Logistic Regression random sampling 재실험
LightGBM feature set 추가 반복 실험
XGBoost / Random Forest 추가 지도학습 실험
fire_label 기준 threshold tuning
```

중단 이유는 모델 성능 부족 자체가 아니라, 문제 정의가 프로젝트 목적과 맞지 않았기 때문이다. 기존 지도학습 모델은 `grid_id-date` 단위 산불 발생 여부를 직접 맞히려 했지만, 산불 미발생 격자를 안전한 negative로 볼 수 없고, 산불 발생은 기상·지형·연료 조건 외에도 발화원, 사람 활동, 우연성, 신고 위치 오차에 크게 영향을 받는다.

### 1.2 새 문제 정의

기존 문제 정의는 다음과 같았다.

```text
이 grid-date에서 산불이 실제로 발생할 것인가?
```

수정 후 문제 정의는 다음과 같다.

```text
전력설비 주변 중 산불 위험 환경에 더 많이 노출되어 우선 관리가 필요한 곳은 어디인가?
```

따라서 최종 산출물은 산불 발생 확률이 아니라, 전력설비 주변 격자 및 전신주의 상대적 위험도 점수와 관리 우선순위가 되어야 한다.

## 2. 전체 작업 흐름

남은 작업은 다음 7단계로 진행한다.

```text
1. 기존 전처리 산출물 품질 확인
2. 위험도 산식 확정
3. grid-date risk score 산출
4. 전신주 단위 risk score 집계
5. decision 기준 적용
6. 시군구별/지역별 위험도 요약
7. 산불 이력 기반 사후 검증 및 시각화
```

작업의 핵심은 다음과 같다.

```text
final_feature_daily 고정
→ pffdri 일자별 percentile 계산
→ 정적 취약도 percentile 계산
→ 전력설비 노출도 percentile 계산
→ final_grid_risk 계산
→ 전신주 grid_id 기준 위험도 매핑
→ 전신주별 max/top5/high-risk-day-ratio 집계
→ pole_risk_score 기준 decision 부여
```

## 4. 1단계: 기존 전처리 산출물 품질 확인

### 4.1 목적

새로운 위험도 스코어링 작업을 시작하기 전에, 최종 feature 산출물이 grid-date 단위로 정상 생성되었는지 확인한다. 전처리를 다시 하지 않는 대신, 최소한의 품질 점검은 반드시 수행한다.

### 4.2 확인 항목

| 점검 항목 | 기준 |
|---|---|
| 행 수 | 예상 기간과 격자 수에 비해 지나치게 작거나 크지 않을 것 |
| 기본 키 중복 | `grid_id + date` 중복이 없을 것 |
| 날짜 범위 | 분석 대상 기간을 포함할 것 |
| 핵심 지수 결측 | `pffdri`, `dwi`, `fmi_n`, `tmi_p`, `pei` 결측이 과도하지 않을 것 |
| 위험도 범위 | `pffdri`가 0~100 또는 의도한 스케일 범위에 있을 것 |
| target 누수 | 위험도 산정 입력에 `fire_label`을 사용하지 않을 것 |

### 4.3 DuckDB 점검 SQL

```sql
SELECT 
    COUNT(*) AS row_count,
    COUNT(DISTINCT grid_id || '_' || CAST(date AS VARCHAR)) AS unique_grid_date,
    MIN(date) AS min_date,
    MAX(date) AS max_date,
    MIN(pffdri) AS min_pffdri,
    MAX(pffdri) AS max_pffdri,
    AVG(pffdri) AS avg_pffdri,
    SUM(CASE WHEN pffdri IS NULL THEN 1 ELSE 0 END) AS null_pffdri,
    SUM(CASE WHEN pei IS NULL THEN 1 ELSE 0 END) AS null_pei,
    SUM(CASE WHEN fmi_n IS NULL THEN 1 ELSE 0 END) AS null_fmi_n,
    SUM(CASE WHEN tmi_p IS NULL THEN 1 ELSE 0 END) AS null_tmi_p
FROM read_parquet('output/final/final_feature_daily/**/*.parquet');
```

중복 확인 SQL은 다음과 같다.

```sql
SELECT grid_id, date, COUNT(*) AS cnt
FROM read_parquet('output/final/final_feature_daily/**/*.parquet')
GROUP BY grid_id, date
HAVING COUNT(*) > 1
LIMIT 20;
```

## 5. 2단계: 위험도 산식 확정

### 5.1 기본 원칙

최종 위험도는 다음 세 요소를 결합한다.

| 구성 요소 | 의미 | 산출 방식 |
|---|---|---|
| Weather Risk | 특정 날짜 내 상대적 기상 위험 | `pffdri` 또는 `dwi`의 일자별 percentile |
| Static Vulnerability | 위치 자체의 산림·지형·접근성 취약도 | `fmi_n`, `tmi_p`, `slope`, `road_prox`, `river_far` 결합 후 전체 percentile |
| Exposure Risk | 전력설비 노출도 | `pei` 또는 `pole_count`의 전체 percentile |

### 5.2 최종 권장 산식

시간 부족과 기존 전처리 산출물 활용 가능성을 고려하여, 다음 산식을 기본안으로 사용한다.

```text
weather_risk
= date별 pffdri percentile rank

static_raw
= 0.40 × fmi_n
+ 0.35 × tmi_p
+ 0.10 × slope_pct
+ 0.075 × road_prox
+ 0.075 × river_far

static_vulnerability
= static_raw의 전체 percentile rank

exposure_risk
= pei의 전체 percentile rank

final_grid_risk
= 0.60 × weather_risk
+ 0.25 × static_vulnerability
+ 0.15 × exposure_risk
```

단, `pffdri` 안에 이미 `FMI`, `TMI_P`, `PEI`가 일부 반영되어 있을 수 있으므로, 보고서에서는 다음과 같이 설명한다.

```text
P-FFDRI는 기존 산불위험지수 기반 종합 위험 기준선으로 사용하고, 정적 취약도와 전력설비 노출도는 전신주 주변 관리 우선순위 산정을 위한 보정 항으로 추가 반영하였다.
```

### 5.3 대안 산식

중복 반영을 더 줄이고 싶을 경우 다음 산식을 대안으로 둘 수 있다.

```text
weather_risk
= date별 dwi percentile rank

final_grid_risk
= 0.60 × weather_risk
+ 0.25 × static_vulnerability
+ 0.15 × exposure_risk
```

다만 기존 최종공모안과 P-FFDRI 흐름을 살리기 위해 본 작업에서는 `pffdri` 기반 산식을 기본안으로 한다.

## 6. 3단계: grid-date risk score 산출

### 6.1 목적

기존 final feature dataset을 이용하여 각 `grid_id-date`의 최종 위험도 점수인 `final_grid_risk`를 산출한다.

### 6.2 작성할 코드

```text
duckDB/build_grid_risk_score.py
```

### 6.3 입력

```text
output/final/final_feature_daily/**/*.parquet
```

### 6.4 출력

```text
output/risk/grid_date_risk/**/*.parquet
```

또는 단일 파일로 저장할 경우:

```text
output/risk/grid_date_risk.parquet
```

### 6.5 생성 컬럼

| 컬럼 | 설명 |
|---|---|
| `grid_id` | 100m 격자 ID |
| `date` | 기준 일자 |
| `pffdri` | 기존 P-FFDRI 점수 |
| `weather_risk` | 일자별 `pffdri` percentile |
| `static_raw` | 산림·지형·접근성 원 점수 |
| `static_vulnerability` | 정적 취약도 percentile |
| `exposure_risk` | 전력설비 노출도 percentile |
| `final_grid_risk` | 최종 grid-date 위험도 점수 |
| `daily_risk_rank` | 해당 날짜 내 위험도 순위 |
| `daily_risk_pct` | 해당 날짜 내 최종 위험도 percentile |
| `daily_high_risk_flag` | 해당 날짜 상위 5% 위험 격자 여부 |

### 6.6 구현 로직

DuckDB 또는 pandas를 사용할 수 있으나, 데이터 크기가 크므로 DuckDB를 우선 사용한다.

```sql
CREATE OR REPLACE TABLE grid_base AS
SELECT
    grid_id,
    date,
    month,
    pffdri,
    ffdri,
    dwi,
    fmi_n,
    tmi_p,
    slope,
    road_prox,
    river_far,
    pei,
    pole_count
FROM read_parquet('output/final/final_feature_daily/**/*.parquet');
```

percentile 계산은 다음 개념으로 수행한다.

```sql
PERCENT_RANK() OVER (PARTITION BY date ORDER BY pffdri) AS weather_risk
PERCENT_RANK() OVER (ORDER BY static_raw) AS static_vulnerability
PERCENT_RANK() OVER (ORDER BY pei) AS exposure_risk
```

최종 점수는 다음과 같이 산출한다.

```sql
0.60 * weather_risk
+ 0.25 * static_vulnerability
+ 0.15 * exposure_risk AS final_grid_risk
```

날짜별 상위 5% flag는 다음과 같이 생성한다.

```sql
CASE WHEN daily_risk_pct >= 0.95 THEN 1 ELSE 0 END AS daily_high_risk_flag
```

### 6.7 품질 확인

산출 후 다음을 확인한다.

```sql
SELECT
    COUNT(*) AS row_count,
    MIN(final_grid_risk) AS min_risk,
    MAX(final_grid_risk) AS max_risk,
    AVG(final_grid_risk) AS avg_risk,
    SUM(CASE WHEN final_grid_risk IS NULL THEN 1 ELSE 0 END) AS null_risk
FROM read_parquet('output/risk/grid_date_risk/**/*.parquet');
```

날짜별 상위 5%가 정상적으로 생성되었는지 확인한다.

```sql
SELECT
    date,
    COUNT(*) AS n_grid,
    SUM(daily_high_risk_flag) AS n_high_risk,
    AVG(daily_high_risk_flag) AS high_risk_ratio
FROM read_parquet('output/risk/grid_date_risk/**/*.parquet')
GROUP BY date
ORDER BY date
LIMIT 20;
```

## 7. 4단계: 전신주 단위 risk score 집계

### 7.1 목적

`grid-date risk score`를 전신주 위치에 매핑하여 전신주별 기간 위험도 점수인 `pole_risk_score`를 산출한다.

### 7.2 작성할 코드

```text
duckDB/build_pole_risk_score.py
```

### 7.3 입력

```text
output/risk/grid_date_risk/**/*.parquet
전신주 위치 또는 전신주-grid 매핑 파일
```

전신주 파일에는 최소한 다음 컬럼 중 하나의 조합이 필요하다.

| 경우 | 필요 컬럼 |
|---|---|
| 이미 grid_id 있음 | `pole_id`, `grid_id` |
| 좌표만 있음 | `pole_id`, `x`, `y` 또는 `lon`, `lat` |

이미 전처리 과정에서 전신주가 grid에 매핑되어 `pole_count`, `pei`가 생성되었다면, 개별 전신주 파일이 별도로 있는지 확인한다. 최종 제출 파일이 전신주 단위라면 반드시 전신주별 식별자와 grid_id가 필요하다.

### 7.4 pole-date risk 생성

전신주별 `grid_id`를 기준으로 `grid_date_risk`를 join한다.

```text
pole_id + grid_id
JOIN
risk.grid_id + risk.date
→ pole_id + date + final_grid_risk
```

### 7.5 pole_risk_score 산식

전신주별 최종 위험도는 다음 산식을 사용한다.

```text
pole_risk_score
= 0.50 × max_daily_risk
+ 0.30 × mean_top5_daily_risk
+ 0.20 × high_risk_day_ratio
```

각 항목의 정의는 다음과 같다.

| 항목 | 정의 |
|---|---|
| `max_daily_risk` | 분석 기간 중 해당 전신주가 경험한 최대 `final_grid_risk` |
| `mean_top5_daily_risk` | 해당 전신주의 위험도 상위 5일 평균 |
| `high_risk_day_ratio` | `daily_high_risk_flag=1`인 날짜 수 / 전체 날짜 수 |

### 7.6 출력 컬럼

| 컬럼 | 설명 |
|---|---|
| `pole_id` | 전신주 ID |
| `grid_id` | 전신주가 위치한 100m 격자 ID |
| `max_daily_risk` | 최대 일 위험도 |
| `mean_top5_daily_risk` | 상위 5일 평균 위험도 |
| `high_risk_day_ratio` | 고위험일 노출 비율 |
| `n_days` | 위험도 계산에 사용된 날짜 수 |
| `pole_risk_score` | 전신주 최종 위험도 점수 |
| `pole_risk_rank` | 전체 전신주 내 위험도 순위 |
| `pole_risk_pct` | 전체 전신주 내 위험도 percentile |

### 7.7 산출물

```text
build_pole_risk_score.py
output/risk/pole_date_risk.parquet
output/risk/pole_risk_score.csv
```

## 8. 5단계: decision 기준 적용

### 8.1 목적

전신주별 `pole_risk_score`를 기준으로 예방 점검 및 순찰 우선순위 대상 여부를 나타내는 `decision` 값을 부여한다.

### 8.2 기본 기준

초기 기준은 다음과 같이 둔다.

```text
pole_risk_score 상위 5% → decision = 1
나머지 → decision = 0
```

### 8.3 민감도 기준

보고서 보완을 위해 여유가 있다면 다음 기준도 함께 산출한다.

```text
decision_top1  = 상위 1%
decision_top3  = 상위 3%
decision_top5  = 상위 5%
decision_top10 = 상위 10%
```

기본 제출 또는 최종 설명에는 `decision_top5`를 사용하고, 나머지는 운영 기준 민감도 분석으로 활용한다.

## 10. 7단계: 산불 이력 기반 사후 검증

### 10.1 목적

산불 이력은 학습 타깃으로 사용하지 않고, 산출된 위험도 점수가 실제 산불 발생 분포와 어느 정도 부합하는지 확인하는 사후 검증 자료로 사용한다.

### 10.2 작성할 코드

```text
duckDB/validate_with_fire_history.py
```

### 10.3 입력

```text
output/risk/grid_date_risk/**/*.parquet
산불발생이력.csv
master_grid 또는 grid geometry 매핑 파일
```

### 10.4 검증 항목

| 검증 항목 | 설명 |
|---|---|
| 발생 위치 위험도 분위수 | 실제 산불 발생 위치 주변 grid의 `final_grid_risk` percentile 확인 |
| 고위험 격자 중첩률 | 상위 5% 위험 격자와 산불 발생 위치의 공간적 중첩 확인 |
| 발생일 위험도 비교 | 산불 발생일의 위험도 분포가 일반일보다 높은지 확인 |
| 시군구별 비교 | 시군구별 평균 위험도와 산불 발생 건수 비교 |
| 사례 검토 | 주요 산불 발생일의 위험도 지도와 발생 위치 비교 |

### 10.5 검증 해석 원칙

다음 원칙을 반드시 지킨다.

```text
산불 발생 위치가 상위 위험 격자에 반드시 포함되어야 하는 것은 아니다.
위험도 모델은 실제 발화 여부를 맞히는 모델이 아니라,
산불 위험 환경에 더 많이 노출된 전력설비 주변 후보지를 선별하는 모델이다.
```

따라서 검증 결과는 모델의 정답률이 아니라, 위험도 산정 결과의 현실 부합성 또는 sanity check로 해석한다.

### 10.6 산출물

```text
output/risk/fire_history_validation.csv
output/risk/fire_history_validation_summary.csv
```

가능하면 다음 그림을 생성한다.

```text
실제 산불 발생 위치의 final_grid_risk percentile 분포
시군구별 평균 위험도 vs 산불 발생 건수 산점도
주요 산불 발생일 위험도 지도
```

## 12. 보고서 수정 방향

### 12.1 1장 분석 배경 및 목표 수정

기존의 “머신러닝 모델이 고위험 격자를 얼마나 효과적으로 포착하는지 검증”이라는 표현은 다음처럼 바꾼다.

```text
실제 산불 발생 이력은 학습 정답이 아니라 사후 검증 자료로 활용하여, 고위험으로 산정된 격자가 실제 발생 이력의 공간·시간적 분포와 어느 정도 부합하는지 위험도 분위수, 상위 위험지역 중첩률, 시군구별 비교, 주요 사례 분석을 통해 검증한다.
```

### 12.2 2장 분석 데이터 및 전처리 수정

`산불 이력 데이터` 설명은 다음처럼 바꾼다.

```text
산불 발생 좌표, 발생 일자, 피해 규모 정보를 활용하되, 예측 피처나 학습 타깃으로 사용하지 않고 위험도 산출 결과의 사후 검증, EDA, 주요 사례 분석에 사용하였다.
```

`최종 분석 데이터와 타깃` 소제목은 다음처럼 바꾼다.

```text
최종 분석 데이터와 산출 단위
```

### 12.3 3장 분석 방법 수정

기존 머신러닝 모델링 장은 삭제하거나 부록/초기 검토로 내리고, 본문은 다음 흐름으로 재구성한다.

```text
3. 분석 방법
  3.1 공식 FFDRI 및 P-FFDRI 산출
  3.2 Weather Risk 산출
  3.3 Static Vulnerability 산출
  3.4 Exposure Risk 산출
  3.5 final_grid_risk 산출
  3.6 전신주 단위 pole_risk_score 집계
  3.7 decision 기준 설정
```

### 12.4 4장 결과 및 검증 수정

기존 `모델 성능 비교` 중심 결과는 다음으로 바꾼다.

```text
4. 결과 및 검증
  4.1 grid-date 위험도 분포
  4.2 전신주별 위험도 우선순위
  4.3 시군구별 위험도 요약
  4.4 산불 이력 기반 사후 검증
  4.5 주요 사례 분석
```

### 12.5 5장 활용방안 수정

최종 활용방안은 다음 문장을 중심으로 정리한다.

```text
본 모델은 개별 전신주의 산불 발생 여부를 직접 예측하기 위한 모델이 아니라, 전력설비 주변의 산불 위험 환경 노출도를 정량화하여 예방 점검 및 순찰 우선순위를 설정하기 위한 의사결정 보조 모델이다.
```

## 15. 최종 결론

현재 시점에서 가장 안전한 전략은 전처리 산출물을 다시 만들지 않고, 기존 `final_feature_daily`를 고정한 뒤 위험도 스코어링 산출물을 추가하는 것이다.

최종 프로젝트는 다음 흐름으로 정리한다.

```text
기존 전처리 산출물 고정
→ P-FFDRI 기반 일별 상대 위험도 산출
→ 정적 취약도 및 전력설비 노출도 결합
→ grid-date final risk score 산출
→ 전신주 단위 기간 위험도 집계
→ 상위 위험 전신주 decision 부여
→ 산불 이력으로 사후 검증
```

보고서의 핵심 메시지는 다음과 같다.

```text
본 연구는 산불 발생 여부를 직접 예측하는 지도학습 모델 대신,
기상위험도, 지형·산림 취약도, 전력설비 노출도를 결합한 위험도 스코어링 모델을 구축하였다.
산불 발생 이력은 학습 타깃이 아니라 산출된 위험도 결과가 실제 산불 발생 분포와 어느 정도 부합하는지 확인하기 위한 사후 검증 자료로 활용하였다.
```
