# 0623 모델 실패 원인 분석 및 방향 수정 계획

## 0. 문서 목적

본 문서는 0622 모델링 전략에 따라 수행한 단일 위험지수, Logistic Regression, LightGBM 실험 결과를 정리하고, 현재 접근 방식의 한계를 분석한 뒤 향후 모델링 방향을 수정하기 위한 문서이다.

초기 모델링은 산불 발생 이력을 이용하여 `grid_id-date` 단위의 산불 발생 여부를 예측하는 방식으로 진행하였다. 그러나 단일 위험지수 baseline과 ML 모델 모두 2024년 전체 모집단 기준 Top-K 평가에서 낮은 성능을 보였고, 특히 샘플 평가와 전체 모집단 평가 사이의 괴리가 매우 크게 나타났다.

이에 본 문서에서는 기존 접근을 단순히 “모델 성능이 낮다”로 해석하지 않고, 문제 정의 자체가 프로젝트 목적과 맞는지 재검토한다. 결론적으로 본 프로젝트는 산불 발생 여부를 직접 맞히는 예측 문제가 아니라, **전력설비 주변 산불 위험도 우선순위 산정 문제**로 재정의하는 것이 적절하다고 판단하였다.

## 1. 기존 모델링 접근 요약

기존 접근은 다음 흐름으로 진행하였다.

```text
산불 발생 이력 좌표 수집
→ 산불 발생 좌표 주변 1km 반경 grid-date에 fire_label=1 부여
→ 나머지 grid-date를 fire_label=0으로 간주
→ positive 전체 + negative sampling
→ Logistic Regression / LightGBM 학습
→ 2024년 전체 모집단 기준 일자별 Top-K 평가
```

라벨 정의는 다음과 같다.

| 구분 | 정의 |
|---|---|
| 분석 단위 | 100m 격자의 `grid_id-date` |
| Positive | 산불 발생일에 산불 발생 좌표 기준 1km 반경 내 격자 |
| Negative | 해당 조건에 포함되지 않은 나머지 격자-일자 |
| Train | 2020~2022년 |
| Validation | 2023년 |
| Test | 2024년 |
| 주요 평가 | 일자별 `Recall@Top-K`, `Lift@Top-K`, `PR-AUC`, `ROC-AUC` |

이 접근은 형식적으로는 이진분류 문제처럼 보이지만, 산불 위험도 문제의 특성과는 완전히 일치하지 않는다. 특히 산불이 발생하지 않은 격자를 모두 안전한 negative로 간주했다는 점이 가장 큰 문제로 판단된다.

## 2. 실험 결과 요약

### 2.1 단일 위험지수 baseline 결과

DWI, FFDRI, P-FFDRI 단일 점수를 기준으로 2024년 전체 모집단에서 일자별 Top-K 평가를 수행하였다.

| 점수 | Top-100 Weighted Recall | Top-1000 Weighted Recall | Top-5000 Weighted Recall | Top-5000 Mean Lift |
|---|---:|---:|---:|---:|
| DWI | 0.0000 | 0.0041 | 0.0213 | 0.9714 |
| FFDRI | 0.0062 | 0.0117 | 0.0254 | 1.1321 |
| P-FFDRI | 0.0007 | 0.0048 | 0.0268 | 1.3402 |

단일 위험지수는 산불위험을 설명하기 위한 도메인 기반 지표임에도 불구하고, 실제 산불 발생 좌표 주변 격자를 Top-K 안에 충분히 올리지 못했다. 특히 P-FFDRI도 Top-5000 기준 Weighted Recall이 약 2.7%에 그쳤다.

이는 P-FFDRI가 의미 없다는 뜻이라기보다, **실제 산불 발생 좌표를 100m 격자 단위 정답으로 두고 맞히는 평가 방식이 위험도 지수의 목적과 맞지 않을 가능성**을 시사한다.

### 2.2 Logistic Regression 결과

Hard negative sampling 조건에서 Logistic Regression을 feature set별로 비교하였다.

| Feature set | Top-100 Weighted Recall | Top-1000 Weighted Recall | Top-5000 Weighted Recall | Top-5000 Mean Lift |
|---|---:|---:|---:|---:|
| index_only | 0.0000 | 0.0021 | 0.0172 | 0.4541 |
| weather_only | 0.0000 | 0.0000 | 0.0000 | 0.0000 |
| compact_full | 0.0000 | 0.0096 | 0.0406 | 1.4627 |
| no_index | 0.0000 | 0.0034 | 0.0296 | 1.1543 |

샘플 평가에서는 ROC-AUC와 Recall이 일정 수준으로 나타났으나, 2024년 전체 모집단 기준 Top-K에서는 실제 산불 발생 격자를 충분히 상위권으로 올리지 못했다.

또한 Logistic Regression의 계수 방향에서도 불안정성이 확인되었다. 예를 들어 `compact_full` 조건에서 `ffdri`, `pffdri` 계수가 음수로 나타났고, `month_num`, `dayofyear`, `day_num` 등 날짜 관련 변수가 크게 반영되었다. 이는 모델이 산불위험의 물리적 구조를 학습했다기보다, 샘플링 구조나 특정 시기 패턴에 영향을 받았을 가능성을 보여준다.

### 2.3 LightGBM 결과

LightGBM은 `compact_full` feature set과 hard negative sampling 조건에서 실험하였다.

#### Threshold 기반 샘플 평가

| 평가 데이터 | ROC-AUC | PR-AUC | Precision | Recall | F2 |
|---|---:|---:|---:|---:|---:|
| Validation | 0.7039 | 0.0264 | 0.0322 | 0.3896 | 0.1210 |
| Test Sample | 0.7257 | 0.0251 | 0.0334 | 0.2999 | 0.1156 |

#### Top-K 평가

| 평가 | K | Weighted Recall@K | Mean Lift@K |
|---|---:|---:|---:|
| Test Sample | 100 | 0.1176 | 13.5146 |
| Test Sample | 500 | 0.4732 | 9.2530 |
| Test Sample | 1000 | 0.6905 | 7.4386 |
| Test Sample | 5000 | 1.0000 | 2.3854 |
| Full Test | 100 | 0.0000 | 0.0000 |
| Full Test | 500 | 0.0000 | 0.0000 |
| Full Test | 1000 | 0.0000 | 0.0000 |
| Full Test | 5000 | 0.0172 | 1.1946 |

LightGBM은 샘플 평가에서는 우수해 보였지만, 전체 모집단 평가에서는 거의 성능을 보이지 못했다. 특히 Test Sample에서는 Top-5000 Weighted Recall이 1.0이었지만, Full Test에서는 0.0172로 급격히 하락하였다.

이는 모델이 전체 격자 공간에서 위험 격자를 정렬하는 능력을 학습했다기보다, **샘플링된 positive/hard negative 분포 안에서만 구분 성능을 보인 것**으로 해석된다.

## 3. 실패 원인 분석

### 3.1 산불 미발생을 안전한 negative로 볼 수 없음

가장 큰 문제는 `fire_label=0`의 의미이다.

기존 지도학습에서는 산불 발생 주변 격자를 positive, 나머지 격자를 negative로 두었다. 그러나 산불이 발생하지 않았다는 사실은 해당 격자가 안전했다는 뜻이 아니다.

```text
위험 조건이 높았지만 발화원이 없어서 산불이 발생하지 않은 경우
위험 조건은 낮았지만 사람 활동이나 우연한 불씨로 산불이 발생한 경우
좌표 품질 또는 신고 위치 오차로 실제 발화 지점과 기록 좌표가 어긋난 경우
```

위와 같은 상황이 모두 가능하다. 따라서 `fire_label=0`은 “안전한 격자”라기보다 “산불 발생이 관측되지 않은 격자”에 가깝다.

이 상태에서 모델을 학습하면, 모델은 기상·지형 조건이 위험한데도 label이 0인 데이터를 대량으로 보게 된다. 그 결과 모델이 기상위험지수와 산불 발생 사이의 관계를 약하게 판단하거나, 오히려 특정 날짜·지역 변수에 의존할 수 있다.

### 3.2 산불 발생 여부는 위험도만으로 결정되지 않음

산불 발생은 다음 요소들이 함께 작용한 결과이다.

```text
산불 발생 = 기상 위험 + 연료 조건 + 지형 조건 + 발화원 + 사람 활동 + 우연성 + 신고/좌표 품질
```

현재 데이터는 기상, 지형, 산림, 전력설비 정보는 일부 포함하고 있지만, 발화원과 사람 활동, 실제 불씨 발생 여부를 충분히 설명하지 못한다. 따라서 현재 데이터만으로 “어느 100m 격자에서 실제로 산불이 날지”를 직접 맞히는 것은 구조적으로 어렵다.

반면 본 프로젝트의 목적은 실제 발화 여부를 점치는 것이 아니라, **산불이 발생할 경우 전력설비 주변에서 위험도가 높은 후보지를 선별하는 것**에 가깝다.

### 3.3 Hard negative sampling이 문제를 악화시킬 수 있음

Hard negative sampling은 `pffdri`가 높은데 산불은 발생하지 않은 격자를 negative로 많이 포함하는 방식이다. 이는 비선형 모델에서는 유용할 가능성이 있지만, 현재 문제에서는 오히려 위험지수의 의미를 왜곡할 수 있다.

예를 들어 `pffdri`가 높은 격자가 다수 negative로 들어가면, 모델은 다음과 같이 학습할 수 있다.

```text
P-FFDRI가 높은 샘플 중에도 label=0이 많다.
따라서 P-FFDRI가 높다고 해서 산불 발생 가능성이 높다고 보기 어렵다.
```

이로 인해 Logistic Regression에서 `pffdri`, `ffdri` 계수가 음수로 나타나는 등 도메인 해석과 맞지 않는 결과가 발생하였다.

### 3.4 샘플 평가와 전체 모집단 평가의 괴리

LightGBM 결과에서 가장 큰 문제는 샘플 평가와 전체 모집단 평가가 크게 달랐다는 점이다.

```text
Test Sample Top-5000 Weighted Recall = 1.0000
Full Test Top-5000 Weighted Recall = 0.0172
```

이는 샘플 평가만으로 모델 성능을 판단하면 매우 위험하다는 것을 보여준다. 샘플 평가는 positive와 negative 비율, negative 추출 방식, hard negative 구성에 의해 성능이 크게 달라질 수 있다. 실제 운영 상황에서는 전체 격자 모집단 중 일부를 고위험 후보로 선별해야 하므로, Full Test Top-K 평가가 더 중요하다.

### 3.5 프로젝트 목적과 타깃 설정의 불일치

기존 접근의 가장 근본적인 문제는 프로젝트 목적과 타깃 설정이 어긋났다는 점이다.

기존 접근은 다음 질문에 답하려 했다.

```text
이 grid-date에서 산불이 실제로 발생할 것인가?
```

그러나 프로젝트가 실제로 답해야 할 질문은 다음에 가깝다.

```text
전력설비 주변 중 산불 위험 환경에 더 많이 노출되어 우선 관리가 필요한 곳은 어디인가?
```

따라서 산불 발생 여부를 직접 타깃으로 두는 방식은 프로젝트 목적을 충분히 반영하지 못한다. 본 프로젝트는 “화재 발생 예측”이 아니라 “화재 위험도 분석 및 관리 우선순위 산정”으로 재정의해야 한다.

## 4. 방향 수정 결론

기존 방향은 다음과 같다.

```text
산불 발생 여부 예측 모델
```

수정 방향은 다음과 같다.

```text
전력설비 주변 산불 위험도 우선순위 모델
```

즉, 앞으로는 `fire_label`을 학습 타깃으로 사용하지 않고, 산불 발생 이력은 사후 검증 및 사례 분석용으로 활용한다.

| 항목 | 기존 방향 | 수정 방향 |
|---|---|---|
| 문제 정의 | 산불 발생 여부 예측 | 전력설비 주변 위험도 우선순위 산정 |
| 타깃 | `fire_label` | 별도 supervised target 없음 |
| 산불 이력 | 학습 정답 라벨 | 사후 검증 자료 |
| 모델 출력 | 산불 발생 확률 | 위험도 점수 및 관리 우선순위 |
| 평가 관점 | 실제 산불 위치를 Top-K에 포함하는지 | 위험 환경·전력설비 취약도를 합리적으로 반영하는지 |
| 최종 산출 | ML probability 기반 decision | 위험도 지수 기반 pole risk score 및 decision |

## 5. 수정된 위험도 모델 설계

### 5.1 전체 구조

수정된 모델은 지도학습 모델이 아니라, 도메인 지수 기반의 scoring model로 설계한다.

```text
일별 기상 위험도
+ 정적 지형·산림 취약도
+ 전력설비 노출도
→ grid-date risk score
→ 전신주 단위 기간 risk score
→ decision 산출
```

### 5.2 구성 요소

| 구성 요소 | 의미 | 후보 변수 |
|---|---|---|
| Weather Risk | 해당 날짜의 기상 산불위험 | `pffdri`, `ffdri`, `dwi`, `effective_humidity`, `wind_ws_max`, `hm_min` |
| Static Vulnerability | 해당 위치의 지형·산림 취약도 | `forest_ratio`, `slope`, `elevation`, `aspect_sin`, `aspect_cos`, `fmi_n`, `tmi_p`, `road_prox`, `river_far` |
| Exposure Risk | 전력설비 노출도 | `pole_count`, `pole_n`, `pei` |

### 5.3 Percentile 기반 정규화

위험도 점수는 원자료 값을 그대로 더하지 않고 percentile rank를 사용한다.

특히 기상위험도는 일자별 percentile을 사용하는 것이 적절하다.

```text
weather_risk = 해당 날짜 내 P-FFDRI percentile rank
```

이유는 다음과 같다.

- 날짜별 전체 위험도 수준이 다르다.
- 같은 P-FFDRI 값이라도 어떤 날에는 높은 위험, 어떤 날에는 평균 수준일 수 있다.
- 최종 목적은 특정 날짜 내에서 상대적으로 위험한 전력설비 주변 후보지를 선별하는 것이다.

정적 취약도와 전력설비 노출도는 전체 격자 기준 percentile을 사용한다.

```text
static_vulnerability = 전체 격자 기준 정적 취약도 percentile
exposure_risk = 전체 격자 기준 전력설비 노출도 percentile
```

### 5.4 1차 제안 산식

초기 산식은 다음과 같이 설정한다.

```text
final_grid_risk
= 0.60 × weather_risk
+ 0.25 × static_vulnerability
+ 0.15 × exposure_risk
```

가중치 설정 이유는 다음과 같다.

| 구성 요소 | 가중치 | 이유 |
|---|---:|---|
| Weather Risk | 0.60 | 산불위험은 기상 조건에 가장 민감하므로 중심축으로 사용 |
| Static Vulnerability | 0.25 | 지형·산림 조건은 위치별 기본 취약도를 설명 |
| Exposure Risk | 0.15 | 전력설비 주변 관리 우선순위 반영 |

이 산식은 최종 확정식이 아니라 1차 baseline이다. 이후 가중치 민감도 분석을 통해 0.5/0.3/0.2, 0.7/0.2/0.1 등과 비교할 수 있다.

### 5.5 대안 산식

선형 결합 외에 곱셈형 산식도 검토할 수 있다.

```text
final_grid_risk
= weather_risk × (0.7 + 0.3 × static_vulnerability) × (0.8 + 0.2 × exposure_risk)
```

곱셈형 산식은 기상 위험이 낮은 날에는 정적 취약도나 전력설비 노출도가 높더라도 최종 위험도가 과도하게 커지지 않는 장점이 있다. 다만 해석과 설명은 선형 결합식이 더 쉽기 때문에, 보고서 본문에서는 선형 결합식을 기본으로 사용하고 곱셈형은 민감도 분석으로 제시하는 것이 적절하다.

## 6. 전신주 단위 decision 산출 방식

최종 제출 또는 운영 활용은 전신주 단위로 이루어져야 한다. 따라서 grid-date risk를 전신주 단위로 집계한다.

### 6.1 산출 흐름

```text
1. grid-date별 final_grid_risk 산출
2. 전신주의 grid_id와 grid-date risk를 매핑
3. pole-date risk 생성
4. 전신주별 기간 위험도 집계
5. 상위 위험 전신주 decision=1 부여
```

### 6.2 전신주별 기간 위험도 집계

전신주별 최종 점수는 다음과 같이 산출한다.

```text
pole_risk_score
= 0.50 × max_daily_risk
+ 0.30 × mean_top5_daily_risk
+ 0.20 × high_risk_day_ratio
```

각 항목의 의미는 다음과 같다.

| 항목 | 의미 |
|---|---|
| `max_daily_risk` | 분석 기간 중 가장 위험했던 순간의 위험도 |
| `mean_top5_daily_risk` | 상위 5개 위험일의 평균 위험도 |
| `high_risk_day_ratio` | 해당 전신주가 고위험일에 자주 노출되었는지 |

`high_risk_day_ratio`는 다음과 같이 정의한다.

```text
high_risk_day_ratio = final_grid_risk가 일자별 상위 5% 이상인 날짜 수 / 전체 분석 날짜 수
```

### 6.3 decision 기준

최종 decision은 전신주별 `pole_risk_score`를 기준으로 산출한다.

```text
상위 5% 전신주 → decision=1
나머지 전신주 → decision=0
```

상위 5% 기준은 초기값이며, 제출 요구사항이나 운영 시나리오에 따라 상위 1%, 3%, 10% 기준도 함께 비교할 수 있다.

## 7. 산불 발생 이력 활용 방식 변경

산불 발생 이력은 더 이상 학습 target으로 사용하지 않는다. 대신 다음 검증에 활용한다.

### 7.1 사후 검증 지표

| 검증 항목 | 내용 |
|---|---|
| 발생 위치 risk percentile | 실제 산불 발생 위치 주변 격자의 위험도 percentile 분포 확인 |
| 고위험 지역 중첩률 | 상위 5% 위험 격자와 산불 발생 위치의 공간적 중첩 확인 |
| 시군구별 비교 | 시군구별 평균 위험도와 산불 발생 건수 비교 |
| 사례 검토 | 주요 산불 발생일의 위험도 지도와 발생 위치 비교 |
| 계절·지역 sanity check | 동해안, 산악권, 내륙권의 위험도 분포가 현실적으로 해석되는지 확인 |

### 7.2 해석 방식

기존에는 산불 발생 위치가 Top-K에 들어가지 않으면 모델이 실패한 것으로 해석했다. 수정 후에는 다음과 같이 해석한다.

```text
위험도 모델은 실제 산불 발생을 확정적으로 맞히는 모델이 아니다.
따라서 산불 발생 이력은 모델의 정답 라벨이 아니라,
위험도 산출 결과가 현실과 어느 정도 부합하는지 확인하기 위한 참고자료로 사용한다.
```

즉, 고위험으로 평가된 지역에서 반드시 산불이 발생해야 하는 것은 아니다. 오히려 고위험 지역은 산불이 발생하지 않았더라도 예방·점검 우선순위가 높은 지역으로 해석할 수 있다.

## 8. 향후 작업 계획

### 8.1 즉시 중단 또는 보류할 작업

다음 작업은 우선순위를 낮춘다.

```text
Logistic Regression random sampling 재실험
LightGBM feature set 추가 반복 실험
XGBoost / Random Forest 추가 지도학습 실험
fire_label 기준 threshold tuning
```

이유는 현재 문제가 단순한 모델 성능 문제가 아니라, 타깃 정의와 프로젝트 목적의 불일치에서 발생했기 때문이다. 지도학습 모델을 추가로 튜닝해도 같은 문제가 반복될 가능성이 높다.

### 8.2 우선 수행할 작업

| 순서 | 작업 | 산출물 |
|---:|---|---|
| 1 | 위험도 산식 확정 | `risk_score_formula.md` 또는 보고서 방법론 문단 |
| 2 | grid-date risk score 산출 코드 작성 | `build_grid_risk_score.py` |
| 3 | 전신주 단위 risk score 집계 | `pole_risk_score.csv` |
| 4 | decision 기준 적용 | `test_hanjeon_with_decision.csv` |
| 5 | 시군구별/지역별 위험도 요약 | `risk_summary_by_city.csv` |
| 6 | 산불 이력 기반 사후 검증 | `fire_history_validation.csv` |
| 7 | 지도 또는 표 시각화 | 위험도 지도, 상위 전신주 표, 시군구 순위표 |

### 8.3 코드 구현 방향

새로운 코드는 다음 단계를 따르는 것이 좋다.

```text
1. master_grid + grid_date_master 결합
2. pffdri 일자별 percentile 계산
3. 정적 취약도 변수 percentile 계산
4. 전력설비 노출도 percentile 계산
5. final_grid_risk 계산
6. 전신주 grid_id 기준으로 위험도 매핑
7. 전신주별 max/top5/high-risk-day-ratio 집계
8. pole_risk_score 기준 decision 부여
```

## 9. 보고서 반영 문장 초안

최종 보고서에는 다음과 같은 흐름으로 반영한다.

```text
초기에는 산불 발생 이력을 이용한 지도학습 기반 예측 모델을 검토하였다. 그러나 산불은 기상·지형 조건뿐 아니라 발화원, 사람의 활동, 우연성에 의해 실제 발생 여부가 결정되므로, 산불이 발생하지 않은 격자·일자를 모두 안전한 negative로 간주하는 것은 적절하지 않다. 특히 위험 조건이 높았음에도 실제 발화가 발생하지 않은 사례가 다수 존재할 수 있어, 발생 여부를 직접 타깃으로 두는 모델은 위험도보다는 특정 날짜나 표본 분포에 의존할 가능성이 있다.

실제로 단일 위험지수, Logistic Regression, LightGBM 실험 모두 2024년 전체 100m 격자 기준 Top-K 평가에서 실제 산불 발생 격자를 충분히 상위권으로 올리지 못하였다. 또한 샘플 평가에서는 성능이 높게 나타났으나 전체 모집단 평가에서는 성능이 급격히 하락하여, 산불 발생 여부를 직접 예측하는 지도학습 접근이 본 과제의 운영 목적과 맞지 않음을 확인하였다.

이에 본 연구에서는 문제를 산불 발생 확정 예측에서 전력설비 주변 산불 위험도 우선순위 산정 문제로 재정의하였다. 최종 위험도는 P-FFDRI 기반 기상위험도, 지형·산림 기반 정적 취약도, 전력설비 노출도를 결합하여 산출하고, 산불 발생 이력은 정답 라벨이 아니라 위험도 산출 결과의 사후 검증 자료로 활용하였다.
```

## 10. 최종 결론

이번 실험의 핵심 결론은 다음과 같다.

```text
산불 발생 여부를 직접 맞히는 지도학습 모델은 현재 데이터 구조와 프로젝트 목적에 적합하지 않다.
```

그 이유는 다음과 같다.

- 산불 미발생 격자를 안전한 negative로 볼 수 없다.
- 산불 발생은 기상·지형 위험뿐 아니라 발화원, 사람 활동, 우연성에 의해 결정된다.
- 실제 목표는 산불 발생 예측이 아니라 전력설비 주변 위험도 우선순위 산정이다.
- 샘플 평가와 전체 모집단 평가의 괴리가 커서 지도학습 모델의 운영 신뢰성이 낮다.
- 단일 위험지수조차 실제 발생 좌표 Top-K 평가에서는 낮게 나왔으므로, 발생 좌표를 정답으로 강제하는 평가 자체가 위험도 분석 목적과 어긋날 수 있다.

따라서 향후 모델링 방향은 다음과 같이 수정한다.

```text
기존: 산불 발생 여부 예측 모델
수정: 전력설비 주변 산불 위험도 우선순위 모델
```

최종 산출물은 산불 발생 확률이 아니라, 전력설비 주변 격자 및 전신주의 상대적 위험도 점수와 관리 우선순위가 되어야 한다.
